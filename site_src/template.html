    The question

    Given the operating readings of a milling machine, how does the choice of decision threshold change the balance between missed failures and false alarms, and how does the best threshold shift as the assumed cost of a missed failure relative to a false alarm changes?

    One row is one operating snapshot of a simulated milling machine. The target is whether that snapshot is a machine failure (1) or not (0). A prediction is made at the moment the readings are taken, using only the readings available then: air and process temperature, rotational speed, torque, tool wear and the machine quality type (L, M or H).

    Failures are rare, so a model can look accurate while catching almost nothing: always answering “no failure” is right 96.6% of the time on our test set. The useful result is therefore not a single accuracy score but three things: how much recall each model reaches at a fixed false-alarm budget, how the cost-optimal threshold moves as the cost ratio changes, and how far the predicted probabilities can be trusted.

    Scope of the claim. This is a prediction test on synthetic data. It shows how methods behave under class imbalance. It does not say how real machines fail, and it says nothing about why they fail.

    Data

    Source: the AI4I 2020 Predictive Maintenance Dataset (Matzka, 2020), UCI Machine Learning Repository, doi:10.24432/C5HS5C. It is public and free to download; its UCI page lists the CC BY 4.0 licence, and the file is included in the repository under data/raw/ with that attribution.

    Quality checks that matter for this question

    • No missing values in any of the 14 columns, so no imputation is needed.
    • Imbalance: 339 failures in 10,000 rows (3.39%). Failure rate by quality type: L 3.9%, M 2.8%, H 2.1%.
    • Target leakage: the five failure-type columns (TWF, HDF, PWF, OSF, RNF) are the components of the target. They are excluded as inputs and used only after prediction, to study errors. UDI and Product ID are identifiers and are also excluded.
    • Label oddities: 9 rows are marked as failures but have no failure-type flag, and 18 rows carry a failure-type flag (random failure) but are marked as not failing. We keep the target column as given and report these rows as they are.

    Preprocessing

    The 80/20 split comes first: a stratified split with fixed seed 42 gives 8,000 training rows (271 failures) and 2,000 test rows (68 failures). Everything learned from data is fitted on training folds only.

    • Scaling and encoding (standardised numeric columns, one-hot quality type) live inside a scikit-learn Pipeline, so each cross-validation fold fits them on its own training part.
    • Physics-informed features are fixed formulas with no learned parameters, so they cannot leak: mechanical power = torque × angular speed, temperature difference = process − air temperature, and tool wear × torque. The dataset documentation describes failure conditions in exactly these terms (heat dissipation needs a small temperature gap at low speed, power failure is a power outside a band, overstrain is wear × torque above a limit).
    • Class imbalance is handled with class weights rather than resampling, so no synthetic rows are created and the test set keeps its natural 3.4% rate.
    • Calibration: class weights push predicted probabilities far above the true rate. We fit sigmoid or isotonic calibration on training folds (whichever has the lower out-of-fold Brier score) and offer both raw and calibrated scores in the interaction above.

    Baselines and methods

    Baseline 1: majority class
    Always predicts “no failure”. It scores 96.6% accuracy and finds none of the failures, which is why accuracy is not our headline metric.
    Baseline 2: logistic regression
    A simple linear model with class weights. It assumes failure odds change smoothly and additively with the readings, which is a fair first guess and easy to interpret.
    Decision tree
    Failure conditions in this machine are thresholds on readings (for example “speed below a limit and temperature gap below a limit”), which is the form a tree learns.
    Random forest
    Averages many trees to reduce the variance of a single tree on only 271 training failures.
    Gradient boosting
    Builds shallow trees in sequence, each correcting the last; suited to interacting threshold rules. Class-weighted histogram boosting from scikit-learn.

    Each model is run twice, on raw features and on raw plus physics features, to test whether domain knowledge helps. Hyperparameters are small grids (listed in the repository) searched by 5-fold stratified cross-validation on PR-AUC.

    Evaluation design

    • Split first, test once. Models, hyperparameters, feature sets, calibration type and every threshold are chosen with 5-fold stratified cross-validation on the training set. The model is picked by cross-validated PR-AUC before test results are looked at.
    • Thresholds are never tuned on the test set. For each cost ratio, the threshold minimises ratio × missed failures + false alarms on out-of-fold training predictions. The test set then shows what that choice would have cost.
    • Primary metric: PR-AUC (average precision), because it ignores the huge pool of easy negatives. A model that knows nothing scores about the failure rate, 0.034.
    • Operational metrics: recall at a fixed false-alarm budget (1%, 2%, 5%, 10% of healthy snapshots), precision, F1, and expected cost for cost ratios from 1:1 to 200:1.
    • Probability quality: Brier score and a reliability curve, before and after calibration.
    • Uncertainty: the spread across the 5 folds, and a 1,000-sample bootstrap of the test set for the chosen model. With only 68 test failures, single numbers are not exact.

    Results

    The physics-informed features matter more than the choice of model, and boosting with those features wins: cross-validated PR-AUC 0.904 against 0.034 for the majority baseline.

    What a false-alarm budget buys

    For the chosen model (gradient boosting with physics features), the threshold is set on training folds so that about the stated share of healthy snapshots raises an alarm, then applied once to the test set.

    How the best threshold moves with cost

    When a missed failure costs about as much as a false alarm, the best policy is to alarm only when the model is nearly certain (a raw-score threshold around 0.92). As the missed failure becomes more expensive, the threshold drops: around 0.77 at 10:1, 0.30 at 16:1, 0.15 at 24:1 and about 0.10 beyond 60:1. The cost curve is flat across a wide middle range, so for a strong model the exact threshold matters little between roughly 0.2 and 0.8 when misses are expensive, but it matters a lot at the low end, where false alarms pile up quickly.

    At the reference ratio of 10:1 the chosen model, using a threshold picked on training folds, caught 59 of 68 failures with 5 false alarms: a cost of 95 false-alarm units against 680 for never alarming and 1,932 for always alarming.

    Can the probabilities be trusted?

    Not the raw ones. Class weights make the model act as if failures were common, so its raw scores overstate the risk and the best threshold on them lands at odd values such as 0.77. After isotonic calibration the Brier score on the test set falls from 0.0173 to 0.0063 and the scores read as probabilities. Calibrated thresholds follow the textbook rule “alarm when the failure probability exceeds 1 ÷ (1 + ratio)” in direction but not exactly (at 10:1 the rule gives 0.09 and our training folds chose about 0.20), a reminder that with 271 training failures the empirical optimum is noisy.

    Errors

    At the reference setting (10:1, training-fold threshold 0.77 on raw scores), the chosen model missed 9 of 68 failures and raised 5 false alarms. Splitting the failures by the type flag they carry shows where the misses come from.

    • Every heat-dissipation, power and overstrain failure was caught (29, 13 and 16). These follow deterministic rules in the data, and the physics features expose them.
    • Tool-wear failures were mostly missed (7 of 10): in the dataset they occur at a random point between 200 and 240 minutes of wear, so no model can tell which tool will fail at which minute.
    • Random failures and unlabelled failures were never caught (4 and 2). Random failures are unpredictable by construction, so recall has a ceiling below 100%.
    • The false alarms are healthy machines running close to a failure limit: four have high torque with high tool wear, and one runs at a power close to the low-power limit. They are plausible warnings rather than nonsense, but the data labels them healthy.

    Limitations

    • Synthetic data. Failure rules were written by the dataset’s author. Our physics features come from those same rules, so the benefit of domain knowledge here is likely larger than it would be on real machines.
    • Few positives. 68 test failures give wide uncertainty: the 95% bootstrap interval for the chosen model’s test PR-AUC is 0.85 to 0.97, and a single missed failure moves recall by 1.5 points. Differences between the top models are within this noise.
    • Optimistic tuning scores. The cross-validated scores are the best of a small grid, so they are slightly optimistic. We report test results for all models for transparency, but selection used only cross-validation.
    • Simple cost model. One fixed cost ratio, no cost that grows with how long a failure goes unnoticed, no cost of inspecting after an alarm, and rows treated as independent snapshots although real machines produce time series.
    • Noisy thresholds. Thresholds come from 271 training failures, so they would shift with a different split. The interaction shows the test-set best threshold next to the chosen one for this reason.
    • Prediction, not causation. A high score means the readings resemble past failures. It does not show that any reading causes a failure.

    Conclusion

    The threshold is a business decision as much as a modelling one: the same model has a best threshold near 0.9 when misses are cheap and near 0.1 when they are costly.

    With physics-informed features, gradient boosting reached 0.92 test PR-AUC and caught 92.6% of failures while raising alarms on 5% of healthy snapshots; the majority baseline catches none. Accuracy barely moves (96.6% for the baseline, 97.4% for the model at a 0.5 threshold), which is why we judged models by PR-AUC, recall at a false-alarm budget and cost. Raw class-weighted probabilities should not be read as risks until they are calibrated. The remaining misses are mostly failures that the data makes random, so a better model would not fix them.

    Reproduce the result

    1. Clone the repository and install the packages: pip install -r requirements.txt (Python 3.10 or newer).
    2. The dataset is already in data/raw/ai4i2020.csv. To fetch it fresh, download it from the UCI link above.
    3. Run python src/pipeline.py from the repository root (about 5 minutes on one CPU core), or run notebooks/analysis.ipynb. It rewrites data/train.csv, data/test.csv, the figures and site_data/results.json.
    4. Run python src/export_tree.py and then python src/build_site.py. This writes one self-contained index.html (styles, scripts, data and figures inline), which you can open straight from disk or publish on GitHub Pages.

    Split: stratified 80/20, random_state=42. Cross-validation: 5-fold stratified, shuffled, seed 42. The test probabilities used by the interaction are precomputed (site_data/results.json); the lab’s small tree is exported by src/export_tree.py from the training split only; no server, credentials or private data are involved.
